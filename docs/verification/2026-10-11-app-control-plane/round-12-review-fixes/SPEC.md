# 审查修复验收合同

日期：2026-10-11。用户已批准四项修复及真实模型、sandbox 和 Electron 验收。本轮不提交、推送或发布。基线为 `codex/app-control-plane` 的 `ea3bad9e6602ccec3484cc55b247bae5815975b4` 加现有未提交内容，输入字节与散列位于 `baseline/`；`baseline/source/` 各文件以 `.txt` 后缀保存原字节。

## 行为与责任

- Main 是任务与未确认写入占用的权威；Service 报告所属执行器事实，模板报告本实例数据库操作事实。renderer 只显示投影。
- HTTP seed/reset 每次绑定 Main 生成的 UUID operationId 与完整实例、任务归属。模板在副作用前登记，重复 ID 不重复执行；取消先到时保留取消记录并拒绝迟到写入。
- 写入取消后保留 App。模型清理与后端操作结束均确认后，才能报告 TaskRun 已取消。已提交数据不回滚。
- 自动核对立即开始，随后每秒一次，总预算 30 秒；未知保留阻塞，用户可在原会话选择“重新核对”。不自动重放或无限查询。
- CLI done/close 未确认时保留句柄与失败事实，任何一个所属执行器或映射未确认都不能被其他成功回执覆盖。
- 元素 ref 必须与 snapshotId 配对；新成功快照替代旧快照，失败快照不覆盖成功引用。testid 合同保持原形状。
- 数据快照保留完整嵌套 JSON，递归对象键排序、数组顺序保留、全量行参与散列、样本上限 20 行。

## 固定验收

| 编号 | 输入与判别 |
| --- | --- |
| F1 | seed/reset 已登记且未完成时取消；App 实例/PID 保持，任务清理待确认，后续写入拒绝；终态确认后才解除 |
| F2 | 取消登记先于原 POST；迟到请求不得执行。重复 ID 同操作复用结果，不同操作冲突 |
| F3 | 响应丢失、查询 not_found/失联/错误实例、30 秒预算耗尽不解除保护；手动核对准确结清原归属 |
| F4 | 模型 cleanup 帧或 done 成功不能覆盖在途后端；取消与迟到 app.reply 不丢清理登记，不串到新轮 |
| F5 | CLI done=false/rejection/close=false 保留归属；stop/start/export 与恢复不会伪造清理成功 |
| F6 | 同文档 Save/Delete 重排并重新快照，旧 ref+snapshotId 拒绝且无输入事件，新引用操作正确 |
| F7 | 导航/detach/实例更换旧引用失效；失败与取消快照保留原成功引用；testid 与用户暂停仍有效 |
| F8 | 真实 PGlite JSONB 嵌套值变化影响样本和散列；对象键序及行序不影响，数组序影响；样本外变化影响散列 |
| F9 | 真实模型完成冻结欢迎语任务，MCP/CLI 新 ref 协议成功，Host 独立固定场景通过；固定基准原字节不变 |

真实后端 gate 只在测试专属生成项目包装原操作；不伪造业务结果，不给产品增加 gate API。任何因权限、凭据或环境无法运行的项目记为 `undetermined`，不得放宽基准或移除断言。测试过程的失败轮次保持原字节。
