# 退出清理回归（2026-10-10）

本轮修复注册表异常导致窗口无法退出且只在控制台报错的问题。交付为 `cf62dc74f49e7f9e81598be7b9e5109cf5946e9c` 之上的本地未提交改动；未改用户真实 `runtime.json` 或 `chat/app-registry.json`，未打包、签名、公证产品或更新安装版，未调用真实模型/sandbox。

## 行为与责任

- Main 的 `ExitCoordinator` 等待安装操作和工作台服务清理；成功后 `getSnapshot()` 等待 Main 的持久化队列，确保最后的应用/终端回执有机会落盘。工作台文件不可读时仍保留原有显式错误日志并关闭。
- 清理失败显示 Electron 原生错误对话框，逐项显示原因，提供重试、取消和仍然退出；默认与 Escape 均为取消。取消保留窗口并说明服务已进入关闭状态。仍然退出明确警告未确认进程可能继续运行，只允许本地窗口关闭，不生成成功清理回执。
- 单次等待上界为 30 秒。超时只结束界面等待；在途尝试仍保留，重试等待同一尝试，不重复发起副作用。实际拒绝后的 Promise 缓存清除，外部问题修复后可重读注册表并再次清理。
- 执行服务先结算受管应用，再尝试对话和环境所有者，保留应用端口清理对共享连接的顺序依赖。应用条目逐项顺序结算并汇总错误，第一条失败不跳过后续条目，也不并发覆盖共享注册表。
- 无效 JSON、空 sandbox 与未来版本拒绝读取并保留原字节。历史运行状态没有进程身份时保持未确认。创建前检查 sandbox 身份；之后按已验证身份写盘，运行状态变成不可用也不会把 sandbox 写成 null。

## 原生窗口检查

主线程使用临时 Electron clone（独立 bundle id、合成注册表、fixture sbx、开发入口；未截获原生 dialog）进行了 CUA 检查。[实际弹窗截图](2026-10-10-shutdown-evidence/native-dialog.png)可见注册表路径、sandbox 无效原因、三个按钮与未确认进程可能继续运行的警告。按 Escape 后取消退出且保留窗口；再次按 ⌘Q 显示同一错误提示。Return 没有观察到状态变化，不能据此声称已验证回车默认取消；默认按钮参数只由单测验证。

点击“仍然退出”后观察到提示关闭，但 CUA 随后似乎自动重启 clone，因此视觉结果不作为进程结束证据；进程结束以最终 5 个 Electron 自动用例明确等待 exit 并断言 exitCode 0 为准。主线程另独立复验最终 56 目标单测、完整 typecheck、本次文件 Prettier、diff 与文档检查，均通过。
