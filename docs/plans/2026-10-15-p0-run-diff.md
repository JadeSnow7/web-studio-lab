## 已确认的设计调整

用户于本轮明确选择「改为宿主保存基线」，并授权既有 `wsl-sbx-smoke-20261006` 的 sandbox live 及原工作包列明的限定真实模型验证。C 的示例仓库 URL 尚未提供。产品用户接受仍需单列，不由测试推导。

原方案的 guest `/home/agent/.wsl-shadow` 只可能约束 Codex 的 `workspace-write` 命令沙箱，不能阻止 A 的同 UID PTY 或 C 的第三方进程改写基线。因此本包不在 guest 保存可信基线，也不把 guest 返回的树哈希或 patch 当作权威证据。

调整后的数据流：

1. guest helper 沿用项目 identity 校验，只读取固定 App 根下的源码；提供有界、可校验的文件内容快照。不运行仓库代码，不读取工程 `.git`，不服从仓库提供的排除规则来隐藏源码。固定排除 `node_modules`、`dist`、`.data`、`data`、`.vite`、`.git`、`.wsl-*`，另排除 `.env`/`.env.*`、凭据配置目录和惯用私钥文件名；完整固定名单见当前运行时与 `source-change.ts`。`.env.example` 同样不进入证据，普通 `src/auth.ts` 仍参与；不承诺识别任意源码中的内联秘密。
2. service 增加独立有限的源码采集操作，校验路径、数量、编码和总字节，确认自己的 helper 清理；不复用或覆盖受管 App 的长期进程句柄、运行状态和日志。App 停止时仍可采集。源码传输有明确上限，超限整体 unavailable，不能静默漏文件。导入仓库上限为 200 MiB / 20000 文件；具体传输预算及任何更小的实现限制必须在交付中明示。
3. Main 在发送模型 prompt 前，将收到的实际内容以排他创建保存在用户数据目录 `runs/<runId>/` 下。宿主建立独立 Git 对象基线并计算 before/after 差异；不使用 guest Git 对象。只用固定 argv 和临时 Git 配置，禁止项目 hooks、filters、外部 diff/textconv 和全局 Git 配置介入。宿主缺少 Git 时明确 unavailable，任务继续。
4. 宿主证据目录不挂载到 sandbox，不作为 service 请求参数发送给 guest。保存基线后的源码变动、guest 的伪造哈希或影子仓库修改不能改变已保存的基线。源码当前内容仍来自不可信 guest；该机制不证明源码作者身份，也不替代独立验收。
5. Main 在模型清理已确认的 completed/failed/cancelled 终态再次采集，并在宿主生成摘要和 `source.patch`。同项目的下一轮不得抢在上一轮结束采集前写入；不同空间仍可独立运行。所有外部 I/O 在元数据队列之外，回队列时复核 run/project 身份与取消。

原 `app.source.snapshot / app.source.diff` 的 guest 树接口相应调整为有界源码采集契约及宿主仓储快照/diff 端口。仅为真实消费者新增端口，不保留空的 guest diff 接口。实现前先定义协议，两端校验。

## 不变量与异常边界

- diff 只记录证据，不改变 validation、review 或用户接受。
- 文件摘要最多 200 项，patch 最多 256 KiB，UTF-8 边界安全截断并显式标记；新增、修改、删除、重命名和二进制均有事实记录。
- 不跟随越界符号链接，不允许路径穿越、大小写/文件目录冲突、特殊文件、重复路径或任意 host 路径。宿主不执行导入项目内容或 Git attributes 中的命令。
- helper 清理已确认时，基线采集失败不阻塞模型启动，终态采集失败只置 unavailable；helper 回执损坏、失联、归属不符或明确清理未确认则阻止模型派发及同项目写入。`sourceCleanupPending` 独立保存，App-only 清理不能解除它；重启保留不确定性，shutdown 必须报告未确认。保存证据失败不能冒充成功；未确认模型清理不能采集结束状态。
- 取消停止新的采集/模型动作，保留已有修改和已保存基线；取消的 run 在所属执行器清理确认后仍采集 diff。必须处理基线采集中取消、迟到回执、发送失败和清理迟到。
- 重启时 baseline 标记 unavailable（「重启前未完成采集」），不自动重采或启动进程；正常旧 schema 4 读取不为默认字段而写文件。
- `runPatch` 由 Main 校验空间/run 归属、只读普通文件和摘要；路径只由可信 runId 派生，拒绝符号链接、目录穿越和散列不符。
- 不改模板、依赖、锁文件、固定验收、安全配置，不改现有注释；每个文件只有一个写入者。

## 实际实现与取舍

- `packages/protocol/src/source-change.ts` 独立定义源码传输、状态和 patch 查询；旧 `AppSourceSchema` 导出上限不变。新增 `app.source.snapshot/cancel`、`workbench:run-patch`、`StudioApi.workbench.runPatch`。请求没有 host 路径或 guest 树参数；service/Main/preload 都校验相应边界。
- helper 输出逐文件、48 KiB 二进制分块及完整回执，service `SourceSnapshotReader` 验证并组装。代码预算为每份 200 MiB 原始字节 / 20000 文件，编码传输上限 352 MiB。额外限制：NFC/有效 UTF-8 路径、1024 路径字节、64 层、20000 目录、单目录 40000 条目；不接受硬链接、符号链接、特殊文件、特殊权限位、控制/格式/行段分隔字符、Unicode 大小写或文件目录冲突。service/Main 也限制文件路径蕴含的目录数量，超出预算即拒绝，避免对无效深层 DTO 无界建表。超限或不支持整体 unavailable。二进制原始内容规范 base64 保留，不以文本解码损坏字节；本轮未完成 200 MiB 满载 IPC/内存压力验证。
- `AppService.sourceSnapshot` 不复用 `command()`，具有独立所属句柄和 120 秒期限；只有内容完整、退出 0、helper confirmed 同时成立才返回。取消等待 helper 自己的清理，未知句柄保留至 shutdown 再尝试，不写 App 日志、不碰长期 App 进程。
- 宿主 `run-source-repository.ts` 采用每 run 的 bare Git 对象库。原始内容通过固定 fast-import 数据流写对象，不在 host 重建 guest 文件树；run 目录、baseline、capture lock、patch 均排他创建，基线/patch fsync，不能重试覆盖既有基线。Git 使用独立环境、禁用外部配置/模板/hooks/filter/textconv/external diff；不改全局或 guest Git。
- Git 在 host 计算 tree、numstat/name-status 和 patch，Git binary 判定原样记录；50% 相似度改名搜索设 200 个非精确候选上限。超过搜索预算仍保留增删事实，不将此上限误称完整重命名检测。摘要最多 200 文件、patch 256 KiB，完整行数先统计，UTF-8 安全截断，SHA-256 针对实际保存/返回的有界 patch。若 Git 将非 UTF-8 字节当作文本而导致待保存的有界 patch 不能安全解码，diff 整项 unavailable，不悄悄替换字符；原始对象保留。
- Main 的队列只保存/归并元数据，注册、源码采集、Git I/O 和发送回执均在队列外。基线先于 prompt；只有 helper 清理已确认的前置失败不阻塞模型。模型清理与 App 合并清理均确认后，completed/failed/cancelled 都采集；同项目占用延续至结束采集完成，采集期用户启动构建也被拒绝，不同项目/空间可独立推进。注册取消、基线取消、发送拒绝、失联启动、迟到 snapshot/turn/cancel 分开处理。
- 退出先取消活动模型、等待采集，再关闭 service；清理不明留下 unavailable 说明。重启不重采，只标记“重启前未完成采集”；正常旧 schema 4 只读不补默认字段。只有 appTarget 明确绑定受管 App 的任务采集，没有项目绑定的任务明确 unavailable。
- patch 从受信 runId 派生固定文件名，核对 workspace/run 归属，不跟随符号链接/硬链接，读取前后检查类型/尺寸/身份并验 SHA-256。Renderer 仅 captured 时请求，响应绑定 workspace/run/hash，并在切换时丢弃旧响应。共用 `PatchView` 保留 Demo OriginBanner，事实文案位于 shared/status；不改变 validation/review。
