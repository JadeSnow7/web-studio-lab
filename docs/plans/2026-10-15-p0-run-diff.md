# P0 D：标准 App 任务源码证据

本切片于 2026-10-21 从 `main` 的 `38af3299417cfe3e49eb8272f0f924f7f376178f` 提取标准 source snapshot/change 完整链。来源为 [#10 的固定提交](https://github.com/JadeSnow7/web-studio-lab/commit/130066850086ffab6295d46e410ae152294a654f)；来源的历史运行记录不作为本组合通过的证据。本文记录当前合同和验收入口，不迁入 edu、Mota、research 或导入产品链。

## 权威与数据流

1. Main 固定 workspace/project/run 身份并持久化采集意图，再请求 guest helper 只读采集标准 App 源码。页面、文件内容和模型输出不能授权另一个工程或宿主路径。
2. Service 校验有界文件帧与完整回执，只在所属 helper 退出和清理确认后返回成功。collector 使用独立句柄，不接管长期 App 进程、状态或日志；运行 App 和停止 App 都可采集。
3. Main 在派发执行前，尝试将实际内容保存到用户数据目录下该 run 独占的 bare Git 对象库和 `baseline.json`。普通基线采集或宿主 Git 失败、但 helper 清理已确认时，按既有合同标记 `sourceChange: unavailable` 并允许模型继续；不将基线成功改为无条件派发门禁。只有清理未知的采集失败阻止派发。guest 不提交权威 Git 树或 patch；宿主证据路径、基线哈希不随模型请求进入 guest。
4. 已保存基线且执行器及其清理确认后，Main 对 completed、failed、cancelled 运行采集结束内容并计算 diff。项目写入占用延续到采集结束；其他空间的独立项目可继续。外部 I/O 不占用元数据队列，回到队列后重新检查 run/project 和取消身份。
5. 只持久化摘要及证据引用到工作台。`workbench.runPatch(workspaceId, runId)` 是现有来源校验下的窄只读 IPC，不接受路径；Main 检查归属、普通文件身份、预算和 SHA-256。任务页只在 captured 时读取，响应必须匹配 workspace/run/hash，切换后的迟到响应不能覆盖当前记录。

## 预算与文件边界

源码采集独立限制为每份 200 MiB 原始字节、20000 文件、20000 目录、48 KiB 分块、352 MiB 编码传输。路径必须有效 UTF-8/NFC，最多 1024 字节、64 层；单目录最多 40000 项。固定排除构建物、运行数据、工程 Git、`.wsl-*`、环境文件、凭据目录与惯用私钥文件名；完整名单由 `packages/protocol/src/source-change.ts` 与 helper 合同定义。不跟随链接，不接受硬链接、特殊文件、特殊权限位、重复路径、大小写或父子别名冲突。它不承诺识别普通源码中的内联秘密。

宿主使用固定 Git argv 与隔离环境，禁止项目 hooks、attributes 外部程序、全局配置参与。文件原始字节进入对象库，不在宿主重建 guest 文件树。基线、capture lock 和 patch 排他创建，不覆盖已有证据。摘要最多 200 文件，patch 最多 256 KiB，截断保留 UTF-8 边界并明确标记；行数合计覆盖完整 diff。改名搜索限制为 200 个非精确候选，不能解释为无限规模的完整改名识别。无法安全解码的文本 patch 整项 unavailable，不替换字节伪造正文。

这些预算不修改已合并的标准源码导出合同（256 文件、524288 字节），也不开放 profile/预算覆盖。200 MiB 满载 IPC 与内存压力仍须单独验证。

## 取消、清理与恢复

- 取消 ACK 不等于进程退出。采集失联、回执损坏或目标不匹配时保留 `sourceCleanupPending` 和项目占用，禁止新执行抢占；App-only 清理不得解除 source 的未知状态。
- 仅在 helper 清理已确认时，普通基线采集或宿主 Git 失败可记 unavailable 后继续执行；该失败策略不改为强制基线成功。意图持久化失败不能启动 helper；基线采集中取消不能继续派发模型。结束采集失败不改写已有 execution/validation/review 事实。
- 重启不重放采集或执行。未完成基线标为 unavailable；模型或 collector 清理未决都继续可见并保留项目占用，不能因重启清除。正常旧 schema 4 没有 source 字段时保持可加载，不补造历史证据。
- 退出等待所属执行与采集操作，未知结果必须保留。不得按进程名或端口清理其他 App。

## 任务页行为

沿用 `RunDetails`、shared status、`.btn` 与既有 diff 着色；无界面重设计。显示基线采集中、等待执行结束、等待清理确认、结束采集中、已采集、无改动、不可用，以及源码清理未知导致的项目占用。源码证据不代表独立检查通过或用户接受。

`PatchView` 每页最多渲染 500 行，保留完整已存 patch。分页与重新读取均使用原生按钮、中文可访问名称；patch 区域可键盘聚焦，长路径可换行。读取失败保留明确错误，只在用户点击后重试；切换 run 或 hash 后丢弃旧响应。沿用只读历史视图与既有演示来源标识，原演示 DiffView 暂不重构。

## 验收入口与覆盖边界

- 协议/Service/Python：source-change、source-snapshot、Python 隔离及实际临时 ROOT walker 测试；覆盖路径、帧、预算、取消与所属清理。Python 标准负例必须进入默认 Vitest 入口，不能只保留未执行脚本。
- Main/真实宿主 Git：source 适配、run-source-application、run-source-repository；覆盖持久化意图、取消/迟到、项目互斥、重启、读写证据身份和恶意 Git 环境。
- 状态投影：shared status facts 负例区分源码证据、检查/审阅、旧历史和清理未知。
- `e2e/p0-run-diff.spec.ts`：使用实际 Main、宿主仓储/Git、preload 和 Renderer；只替换明确选中的 Service source/model 输入，覆盖状态、patch 哈希、取消、迟到响应、退出清理、超过十万行分页、读取失败/错误身份/显式重试、键盘与窄窗深色主题。
