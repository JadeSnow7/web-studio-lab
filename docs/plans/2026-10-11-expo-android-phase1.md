# Expo Android 第一阶段实施与验收计划

按“冻结工具链与端口实验 → 创建与协议 → Web 预览 → USB 真机 → APK 构建 → 整体验收”推进。完成标准是同一 Expo 项目经过 AI 修改后，在工作台和 Android 真机看到变化，并导出停止开发服务后仍能独立运行、再次导出可覆盖升级的 APK。

状态：待实施。日期：2026-10-11，Asia/Shanghai。用户已确认 USB 优先，本轮仅制定文档，不执行下列工作包。实现方案以[设计文档](../design/2026-10-11-expo-android-phase1.md)为准；本计划中的拟新增文件、命令和证据是未来交付要求，不能据此判断已存在或已通过。

## 范围和角色

维持每空间一个 App，Expo 为第二个明确模板，第一阶段只支持 macOS Apple Silicon 宿主、Android ARM64 真机、USB Expo Go 预览和本地 release APK。无 EAS、无线连接、iOS、AAB、商店发布、任意依赖/原生插件、自动安装 APK。既有 Web 模板和 VS001 的验收要求保持。

主线程负责需求、设计、冻结验收、独立 diff 审查、现场验收和交付。每个源码/检查脚本工作包委派给 `coder`，按下表分配文件责任；共享 protocol/Main/service 接线串行修改，同一文件不分给多个写入者。后续实施授权前，不启动 P0 的安装、sandbox、设备或构建动作。

## 固定验收样例

样例是一页离线清单：本地图标、标题“随身清单”、输入框、“添加”按钮、条目列表、完成切换、删除。通过固定的本地存储接口保存条目；Web 与 Android 数据隔离。预先建立两条条目，其中一条完成。

固定修改任务为：“把添加按钮改成‘加入清单’，新增空白输入提示‘请先输入内容’，保留已有条目、完成切换和删除行为。”验收先在原版检出按钮/提示不满足，再对同一修改后的输入复验。测试基准在 Agent 写入范围外，Agent 不得改测试期望值或通过删掉输入校验来通过。

协议与固定内容基准可在 P0 冻结，实际适合当前 SDK 的选择器在 P2 真窗口建立并记录。不得把 Web DOM 选择器当作原生 Android 定位器；真机步骤由实际设备操作和录屏/截图、冷启动、存储结果证明。
