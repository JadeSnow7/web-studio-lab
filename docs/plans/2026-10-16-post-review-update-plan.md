### R3 · App 异步异常与清理状态

- 处理完整 Promise 链，包括 `done` 正常完成后 `cleanup()`、`persist()`、状态发布的异步失败。
- 使用现有合法状态，不直接写不存在的 `unavailable`；核对当前进程与 AppInstance，阻止旧实例迟到异常污染新实例。
- 持久化失败不伪造清理成功，不释放清理尚未确认的许可。
- 限定范围引入类型感知 Promise 检查，明确 `ignoreVoid: false` 并有 lint 负例。

验收覆盖：正常完成后持久化失败、清理失败、旧实例迟到失败、替身 `done` 拒绝；无未处理拒绝，错误可见且恢复可继续。

### R4 · Mota 违规检测与启动能力门禁

- 在 started/updated/completed 事件统一检测 `command_execution`。违规终态带 `policy_violation`，是失败而非用户取消。
- 同步关闭后续工具入口、撤销在途请求；迟到请求不得进入 dispatcher，迟到成功不能覆盖失败。
- 核对固定 guest Codex 版本及实际 `exec` 参数能力，不从 `sandbox` 子命令报错推导产品参数。
- 需要“仅四个专用工具”的模式必须验证原生能力限制；不支持或无法确认则拒绝启动，不回退提示词。
- 保留已产生的合法修改和回执；清理未确认时保留占用和可见状态。

本包证明检测、撤销和启动门禁，不宣称执行事件是执行前审批，也不宣称完成 OS 文件/网络隔离。该能力另由 S4 验证。

### R5 · 统一现有导出合同，不扩大预算

| Profile      | 文件数 | 解码后源码总量 | 支持导出 |
| ------------ | ------ | -------------- | -------- |
| standard-app | 256    | 524288 字节    | 是       |
| edu-web      | 256    | 524288 字节    | 是       |
| mota-web     | —      | —              | 否       |

- 显式导出预算表，解除标准导出对 edu 常量命名的耦合。
- 预算仅从可信 service→helper 通路传递，页面/renderer 不得指定或扩大预算。
- protocol、service、helper、Desktop 落盘验证一致；区分源码、执行副本与 base64/JSON 传输预算。
- 文件数和字节数覆盖 limit−1/limit/limit+1、多字节及编码膨胀；超限整体拒绝，不留下半份有效导出。

这是现有合同一致化，不是恢复原本不存在的端到端 8 MiB 支持。

### R6 · 可信编辑入口与保存授权

- 保存收敛到 Main 具名用例，可信编辑资产由产品提供，不将导入的编辑器脚本视为可信代码。
- 游戏 Browser 不公开可被其直接利用的宿主写入能力。
- 请求绑定项目、AppInstance、文档/会话、目标文件与预期内容哈希，继续检查白名单、内容、原子替换及 AI 租约互斥。
- nonce 仅表示快照会话，不承担授权；不使用无请求范围限制的 `Network.setExtraHTTPHeaders` 作为核心边界。
- 若必须保留原导入编辑器，先验证独立 origin、可信脚本和请求级授权，不能只换端口就宣布安全。

验收覆盖恶意游戏/编辑器、直接 HTTP、导航后旧授权、错误实例、版本冲突、AI 占用及正常人工保存。

## 四、条件性扩展

准入顺序：范围批准与 ADR → 必要安全修复 → 最小运行环境端口及 sbx 行为不变迁移 → Harness 端口及 Codex 行为不变迁移 → Claude Code 适配器。SSH、本机执行分别作为独立能力包，不默认并行实施。

- Harness 每轮绑定 run/generation、任务版本、权限和环境；取消返回结构化清理结果，允许未确认。各用原生事件 fixture，共享契约断言，并有真实子进程退出证据；不自动切换 Harness，不复制宿主凭据。
- 运行环境分别记录类型、具体实例、配置版本和已验证隔离能力。SSH 不是隔离等级，SFTP 范围不证明 exec 隔离；断线不等于远端停止。端口转发限定回环并核对 App 身份。本机执行默认关闭。
- 布局预设可独立交付，但不得隐藏授权、运行、取消或清理未知。浏览/设计完整工作流依赖真实产品检查器与报告接线，页面现场仍经显式选择与任务确认。
- 产品内接受必须绑定验证结果与代码版本；外部人工验收另行标识，不能将运行或外部回执自动转成产品验证通过。
- Rein、容器、远程部署、Expo、设计令牌、Windows/Linux 包保留后续评估。若交付正式 macOS 安装包，签名与公证是该交付门槛；内部未签名包明确标识。

## 五、验证与交付规则

- 每包：先建立可检出问题的测试，再实现，跑相关类型、lint、格式和回归。
- 合并候选：完整检查链、Linux 必跑、构建、自检、默认 Electron E2E；不能用其他工作树结果替代。
- 新安全能力：实际目标环境探针；未运行不得标为支持，不从 canary 未变推断隔离成立。
- 决赛冻结：只对实际纳入能力执行相应 live/packaged 验收，保留失败和人工介入。
- 用户接受：用户确认具体构建，独立于执行结束和自动检查。

回执绑定提交、源码/构建指纹、工具版本与实际环境，使用 `passed`、`failed`、`undetermined`、`not_run` 并限定范围。原始大候选的审查规模另列；后续小修复不意味着原 PR 已被拆分。默认不提交、不推送、不合并、不发布，不将计划能力提前写成实现。
