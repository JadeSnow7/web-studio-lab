# VS001：Agent 修改固定页面的首个闭环

本基准只冻结一个可复跑场景及其验收入口，不实现 Electron 工作台。产品基线是 `536f0a1948e522a09310aa20784ec512476dc7be`；本次加入的依赖仅服务测试和固定页面 fixture。未来实现须先保存本基准的失败结果，再以相同基准内容复验。

## 成功条件与边界

一次运行必须完成：真实现成 Agent harness 修改运行副本中的 `src/App.tsx` → 启动 Electron 中的预览页面 → 基准直接通过 CDP 读取同一页面状态 → 独立执行 postcondition → 保存该页面截图与原始日志。

固定输入是 React/TypeScript 页面，唯一标题元素为 `[data-testid="greeting"]`，初始可见文本为 `Hello baseline`。固定任务是把它改为 `Hello Web Studio`，不修改其他文件。每次从未改动的 fixture 创建新副本，原 fixture、测试和契约均不交给 Agent 修改。任务只能使用一次真实 harness 会话；本基准不加入自动修复或重试。

验收对象是 Electron Browser 区的页面实例，必须明确 `webContentsId`、CDP `targetId` 和带本次 `runId` 的回环 preview URL。观察与截图使用同一条 CDP 连接。产品适配器不得返回 DOM 求值结果、postcondition 布尔值或代制截图；这些由验收端生成。CDP 的 Electron User-Agent 和进程存活由基准核验；`webContentsId → targetId` 的对应还须审阅产品适配代码，不能声称 CDP 能独立证明该映射。

首个 slice 不要求完整 Workshop 布局、编辑器、xterm.js/node-pty 交互终端、Hono 业务 API、多模板、多 Agent、持久化历史或安装包。它们不进入本次依赖或验收门槛。后续应用 API 可使用 Node/Hono，桌面通信用受限 IPC；本基准不另建工作台 HTTP 服务。

## 唯一契约与职责

`tests/vertical-slice/contracts.ts` 是 Zod 任务、产品事件和适配器接口的唯一权威来源。文档解释语义，不复制第二份字段定义。任务在启动前冻结；严格校验外部任务、事件和 CDP 回包，不信任产品自报的通过状态。

未来产品入口固定为 `src/vertical-slice/adapter.ts`，导出 `executeTask(task, context)`。context 提供隔离副本路径、事件/原始 harness 输出回调、AbortSignal 与 `registerCleanup`；返回应用身份和回环 CDP endpoint。适配器负责：

1. 调用现成 Agent harness（首选已有 Codex CLI 路线），记录实际版本、模型、会话、进程命令和退出码；绝不以字符串替换器冒充 Agent。
2. 只修改任务允许的页面文件；保存原始 harness 输出，不保存密钥或整个环境变量。
3. Agent 成功退出后，启动固定页面的 Vite 服务和最薄 Electron 宿主，将待测页面停留在 `about:blank`；只有页面可接受 CDP 时才报告 ready，并返回待导航的、包含 runId 的 preview URL。基准启用 Runtime/Page 事件订阅后亲自导航，以捕获初次加载异常。
4. 创建每个资源时立即通过 `registerCleanup` 注册释放方法；不能等 executeTask 成功返回才交出清理能力。收到 abort 后停止继续创建资源。无论验收成功、失败或超时，都释放本次启动的 Electron、Vite 和 Agent 子进程。不得关闭其他运行的进程。

基准负责创建 runId/任务指纹、复制 fixture、保存输入快照、记录所有事件、比较文件变化、亲自连接 CDP、执行断言、捕获截图和日志、生成 manifest 以及最终非零/零退出码。适配器暂不提供，实现缺失应清楚暴露为失败，不新增永远抛错的产品占位实现。

基准自检独立于这五条产品验收，使用明确标为合成的样本检查契约、postcondition 和证据绑定的拒绝能力。自检通过不使产品闭环变绿。禁止 skip、todo、预期失败转成功或 mock adapter 接入产品验收命令。

## 同一次运行的证据绑定

每次运行创建 `records/vertical-slice/<runId>/`，已存在的目录必须拒绝覆盖。runId 为新 UUID；taskId 固定 `VS001`。任务及 allowedPaths 在调用适配器前冻结，序列化后按实际字节计算 task SHA-256。产品生命周期事件带 runId、task 指纹、严格递增 seq 和时间；原始日志逐行追加并带 runId、task 指纹和采集时间，CDP 请求/响应再以 request id 配对。重跑是新的 runId，不重用旧目录。

基准指纹覆盖本文件、契约、测试/执行器、postcondition、全部 fixture、依赖清单及锁文件。manifest 保存逐文件 SHA-256 和合成指纹；它和任务指纹用途不同，不通过更新版本字符串冒充相同基准。运行环境另外记录 Node、平台、Git HEAD、工作区改动及入口内容哈希。实现前后允许产品 revision 变化，但基准指纹必须相同。

同目录保留冻结 task、输入/修改后文件、文件变化清单、事件 NDJSON、harness 原始输出、应用输出、CDP 请求/响应/通知、原始 observation、postcondition 结果、PNG 和最终 report/manifest。源文件快照与变化清单只排除运行副本顶层的 `node_modules/`、`dist/`、`.vite/` 三类生成目录，其余新增、删除和修改都纳入比较；符号链接直接拒绝。零 console 消息也要有观测开始/结束边界；缺日志和空观察窗口不能等同于无错误。截图只能来自本次 CDP `Page.captureScreenshot` 回包。

manifest 为每个产物记录相对路径、字节数和 SHA-256，并绑定 runId、task 指纹、基准指纹、targetId/webContentsId、采集开始结束时间和五项结果。manifest 不把自身哈希放入自身；外层运行回执可记录它的哈希。哈希用于防止误混/篡改，并不能密码学证明 Agent 或适配器诚实；真实 harness 来源及产品适配代码仍需审阅。

失败也必须保存实际已有的证据和错误阶段；未调用 CDP 时不创建虚假 observation/PNG。原始 CDP 错误、超时、断连及 harness 非零退出不能吞掉、静默降级或改连其他 target。单次期限为 120 秒、单次 CDP 请求上限为 10 秒，作为防挂死参数，不是性能承诺。验收终态写入前应完成本次资源清理。

## 执行与解释

具体命令、实际文件树和本次实现前回执见同目录 `README.md`。运行顺序是安装锁定依赖 → 基准自检/类型检查 → 执行五条验收并保存非零结果 → 主线程审阅失败原因 → 后续任务才实现产品入口 → 原样复跑并比较基准指纹。不得为配合产品实现降低断言；方法缺陷须说明原因、保留旧结果并另建基准版本。
