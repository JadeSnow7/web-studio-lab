## 1. 目标与交付日期

### 1.1 本次交付目标

Web Studio Lab 是以运行页面为中心的意图驱动 Web 开发环境。开发者从页面现场表达修改目标，系统组织代码修改、运行、检查和证据；开发者决定结果是否满足目标。

在一套固定模板和固定初始数据上，演示并复验三类跨层修改：

1. 新增一个持久化字段。
2. 修改一个服务端权限规则。
3. 修复一个前后端字段不一致问题。

固定流程：**点选页面元素 → 采集现场 → 确认目标与验收 → Agent 修改代码 → 启动与检查 → 预算内修复 → 展示差异、结果和证据。**

每个用例都要产生可查看的代码差异、真实运行结果和固定验收证据。单次成功演示只支持该次结果，不外推为通用开发成功率；没有对照数据时只报告案例结果。

### 2.2 两层技术栈与职责

| 层次 | 已确认路线 | 本轮边界 |
| --- | --- | --- |
| 桌面宿主 | Electron + TypeScript；主进程管理窗口、页面身份、布局、CDP 与 IPC | T14 验证 macOS Apple Silicon 打包与同页控制 |
| 工作台 UI | React + Vite，Workshop / Browser 双区 | P0 为任务确认、运行阶段、日志、源码 / diff 和结果；完整内嵌编辑器后置 |
| 执行服务 | 独立 Node 进程，管理 Codex、构建、测试、开发服务与运行记录 | 桌面通过限定 IPC 调用；每个工作空间只有一个活动 run |
| 工作台通信 | preload 暴露有限能力，限定 IPC 与执行事件 | 取消原稿独立 Hono / WebSocket 工作台服务安排；Hono 用于生成 App API |
| Agent | Codex CLI 非交互调用 + 薄 adapter，单 Agent | 归一化 JSONL 事件；T02 成功后冻结有效 CLI、模型与参数，不自研推理循环 |
| 页面工具 | 本地、绑定当前 run 的 MCP 接入 | 首版限读取、元素点击、输入、截图和相关诊断；宿主校验目标身份 |
| 协议 | Zod 定义最小任务、页面快照、运行事件、命令结果与验收结果 | 保留以后接入 Rein 的边界，不提前做通用运行时 |
| 运行记录 | JSON / JSONL + 文件证据 | SQLite 历史索引为 P1；文件证据能独立读取 |
| 开发浏览器 | `WebContentsView` 的同一 `webContents`，主进程通过 CDP 控制 | 用户观看、Agent 操作与开发诊断绑定同页 |
| 唯一生成 App | React + Vite + Hono + Drizzle + Zod + Tailwind / shadcn | 一个任务管理模板，不增加第二套模板 |
| App 数据库 | API 进程持有 PGlite，独立持久化目录 | 预置 A/B 测试身份，不扩展完整注册 / OAuth / RBAC |
| 验证 | Vitest + Playwright 与固定独立验收 | 独立 E2E 使用新 context，身份与结果单独记录 |
| 交互终端 | P1：xterm.js + node-pty | P0 的退出码、就绪与取消来自结构化执行服务 |

从仓库根目录组织 pnpm workspace，拟包含 `apps/`、`packages/protocol/`、`templates/`、`fixtures/` 与 `acceptance/`；不建立另套 `competition/` 工程。生成副本和本地证据位于 `.local/` 下。以上目录待实现；固定 fixture 与验收留在 Agent 写入范围外。

执行服务亲自记录命令、工作目录、stdout / stderr 与退出码；开发服务还需就绪检查。终端画面、CLI 正常退出、服务 ready 和业务验收分别判断。工作台 renderer 通过 preload 获得有限能力；目标 App 页面不获得文件或进程接口。[Electron 安全边界][electron-security]

### 2.3 页面意图与同页控制

1. Browser 显示实际 App，提供地址、刷新与选择模式。开启选择模式后点击元素，采集元素摘要、页面地址、截图和运行错误。
2. Workshop 展示现场资料、修改目标、允许修改的项目、验收条件与运行预算。开发者确认后固定这一轮输入；改变目标或验收产生新版本，保留已有失败结果。
3. Agent 修改生成副本，执行服务启动与检查；失败证据在预算内返回同一 harness 修复。展示源码差异与每项检查结果，开发者判断是否接受。
4. 页面导航后更新现场，旧元素引用不继续使用。人工 DevTools 导致 CDP 断开时暂停页面自动操作并显示原因；重新附着后重新采集现场。

`WebContentsView` 的布局由主进程管理，与 React 双区布局同步。用户观看、Agent 操作、截图与开发诊断绑定同一 `webContents`；独立 E2E 记录其新 context，不混用页面身份。[页面接口][electron-view]、[Debugger][electron-debugger]

### 2.4 本轮排除项

Rust 核心、自研 Rein 运行时、第二套模板、Expo / 原生移动端、生成 App 的上传功能、后台任务、实时协作、生成 App 的云部署、通用 WASM / Docker 沙箱平台、WebContainers、产品内多 Agent 编排、复杂回放播放器、完整内嵌编辑器、截图批注、操作录制与多页面编排。

本轮运行边界是本地固定模板与明确工作目录。PGlite 是数据库，不承担代码执行沙箱职责；当前计划不承诺公共多租户或任意不可信仓库的安全运行能力。原生终端移植不列入本轮。

| 用例 | 固定用户意图与初始条件 | 必须通过的验收 | 不能作为通过依据 |

A/B 身份来自受控测试会话或现有认证路径，服务端按可信会话判断当前用户；不要把客户端请求中的用户 ID 当作权限证明。各用例单独恢复代码与数据库，不依赖前一用例的残留状态。

## 7. 最小运行与证据约定

### 7.1 标识和记录

| 字段 | 用途 |
| --- | --- |
| `taskVersion` | 关联执行前确认的目标、允许项目、验收条件与预算；变更形成新版本 |
| `workspaceId` | 定位生成 App 的工作目录与数据 |
| `runId` | 标识一次完整用户任务或一次独立复验 |
| `attemptId` | 标识该 run 内的一次修改与验收尝试 |
| `requestId` | 关联单个 HTTP 请求的前后端日志；按需记录 |
| `seq`、`timestamp`、`type` | 事件排序、时间与种类 |
| `mode` | `online` / `revalidate` / `replay` |
| `sourceState` | 基线 commit + diff / 内容哈希；不能只记录脏工作区的 HEAD |
| 页面现场引用 | 页面地址、`webContents` 身份、采集时间、元素摘要、截图与相关错误；标记导航后失效 |
| `fixtureVersion`、`acceptanceHash` | 明确初始数据和固定验收版本 |
| 结果与 artifact 引用 | 命令、退出码、错误、日志、截图 / trace、验收结果路径 |

最小事件包括：任务确认、现场采集 / 失效、开始、attempt 开始、文件变更摘要、命令开始 / 结束、服务 ready、CDP 暂停 / 重新附着、验收结果、证据新增、run 终态。由工作台归一化现成 harness 事件，未知事件可保留原文，不把解析缺失伪装成成功。

输出建议为一个 manifest、一份有序 JSONL 事件流，以及按需产生的日志、截图、Playwright trace。先覆盖三个用例，不制作通用追踪平台。

交付时把各用例最终源码快照和必要证据导出为仓库内样例或版本绑定的发布资产；源码必须包含新增文件、迁移与锁文件，不能只有未提交 diff。manifest 使用包内相对路径，记录快照哈希与原始基线。临时目录中的源代码和文件不可视为已经交付；必须在干净检出 / 下载后按同一入口完成复验。

### 7.2 数据与浏览器生命周期

- PGlite 在 API 进程中持有，每个工作空间使用独立持久化目录；验收数据与演示数据分开。
- API 活跃时，不让另一个验证进程直接打开同一数据库目录。优先通过 API 核对；确需独立 SQL 检查时，先完成关闭与所有权交接。
- 验收“持久化”必须包含进程停止和重启，且重启验证前不能重新写入预期数据。
- 记录实际预览的 `webContents`、URL、session 和 App 实例；用户观看、Agent 操作与开发诊断绑定同一页面。导航后刷新现场并识别旧元素引用失效。
- 最终 E2E 可以创建全新 browser context，但须显式准备身份与初始数据。新 context 的结果与开发预览记录分别标识。
- 取消、超时和应用退出时等待所属进程清理；隐藏面板保留运行实例，恢复历史描述不自动重启进程。终端停止输出不能代替清理完成。
- 人工 DevTools 导致 CDP 断开时暂停页面自动操作并显示原因；重新附着后重新采集现场。
- 任务确认后输入固定；目标或验收条件变化产生新版本，保留已有失败结果。工具故障显示“无法判断”，不合并为业务成功或失败。

### 7.3 三种模式及统计口径

| 模式 | 实际执行 | 是否调用模型 | 可证明的内容 |
| --- | --- | --- | --- |
| 在线运行 | 从固定初始状态请求 AI 修改，再运行验收 | 是 | 本次模型与配置完成任务的结果 |
| 无模型复验 | 启动指定最终代码，重新执行固定验收 | 否 | 当前环境下该代码仍满足指定验收 |
| 历史查看 | 读取旧事件与证据 | 否 | 过去记录了哪些结果 |

“无模型复验”不等于无网络安装：首次安装仍可能需要依赖与浏览器下载，README 应明确这一点。若评审环境要求全离线，另行核对依赖打包要求与成本。

指标至少记录用例、模型 / harness 版本、初始状态、预算、实际 attempt 数、通过与否、耗时、人工介入次数、用户补充上下文次数和失败原因。人工改代码、补关键提示、修改配置或手动恢复数据都应记入介入。在线运行、复验和历史查看分开统计；三个用例各跑一次就如实写“3 个样例、各 1 次”。

“用户补充上下文次数”用于观察页面现场是否减少解释工作；没有对照数据时仅报告真实案例，不宣称效率提升比例。CLI 退出码、服务 ready 与独立验收分别记录，不能相互替代。

## 8. 拟固定的命令入口

以下是待实现的脚本契约，**不是当前仓库已有命令的说明**。统一从仓库根目录执行，实际参数与安装前提在 T03 / T09 / T14 落实到 README。

| 命令 / pnpm script | 约定 |
| --- | --- |
| `pnpm install --frozen-lockfile` | 使用锁文件安装；列明 Node、pnpm、Electron 与测试浏览器准备步骤 |
| `pnpm dev` | 启动 Electron 双区工作台及独立执行服务 |
| `pnpm app:dev` | 启动指定生成副本的 API 与前端，报告预览地址 |
| `pnpm db:migrate` / `pnpm db:seed` | 指定工作空间迁移与初始化，不隐式覆盖其他数据 |
| `pnpm check` / `pnpm build` | 正常工作台 / 母模板的固定类型、单元检查与构建入口 |
| `pnpm package` | 生成 macOS Apple Silicon 试用包；打包成功后仍须进行包内运行验收 |
| `pnpm demo:reset` | 只在登记的演示副本中恢复指定用例初态 |
| `pnpm demo:run` | 指定用例、已确认任务版本与预算，启动真实在线 run |
| `pnpm verify` | 工作台控制的固定验收，失败返回非零退出码 |
| `pnpm revalidate` | 从指定最终源码与用例重新执行同一验收，产生无模型新记录 |
| `pnpm replay` | 读取已有证据，标明历史查看，不触发模型或旧进程 |

入口显式接受工作空间、用例或 run 标识，记录实际命令与退出码。重置只作用于已登记的演示副本，不能重置用户正在编辑的源仓库。

在线运行说明列明用户自行准备的 Codex 配置与有效组合；CI 使用无模型检查，不要求模型凭据。无模型复验的首次安装可能需要网络。命令与版本实际验证前不写成“已可用”。
