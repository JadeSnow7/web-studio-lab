## 1. 目标与原则

目标：让“浏览 → 对话 → 开发 → 验收”闭环的每一步都在原地完成，用户不需要为了把功能接起来而手动跳页、预先选择或打开弹层。

| 原则             | 含义                                                                                                                                                          |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P-1 默认可见可改 | 以“可见的默认值 + 一次点击可改”替代“操作前必须显式选择”；接收者与页面身份在**采集发起时**冻结，任务输入在**发送时**冻结，迟到结果规则不变                     |
| P-2 单一路径     | 同一件事只有一个主入口；同一份数据只有一个输入框                                                                                                              |
| P-3 原地完成     | 操作结果出现在用户当前看着的地方；不为完成一步而切换板块或子页                                                                                                |
| P-4 页面不消失   | 迁移为原生菜单的弹层不再让原生网页让位；模态对话框、临时侧栏、状态列表与 ⌘K 面板仍进入遮挡集合                                                                |
| P-5 不展示空壳   | 未接入的能力不出现在常规界面，也不显示为故障；接受门槛不因此放宽                                                                                              |
| P-6 键盘可达     | 高频操作都有菜单加速键（焦点在原生网页时 renderer 收不到按键，见 `apps/desktop/src/main/menu.ts`）；⌘Enter 与 Esc 只由 renderer 处理，不注册为加速键（见 R4） |

不变边界：Main 仍是业务状态单点写入者；renderer 不调用 Node/Electron，新增 IPC 为具名窄接口且由 Main 校验来源与输入；执行结束、检查通过、用户接受仍分别记录；关闭标签不停止实例；中文 IME 组词期间 Enter 不提交；页面、菜单上下文与工具输出是数据，不授予权限。

## 3. 范围

本轮做 **OPS-a（S1–S5）与 OPS-b 的 S6–S9**（D6 = B）。S10 与 OPS-c 延后，保留在本文件中但不进入本轮验收。

### OPS-a（P0）

**S1 一步点选。**

- 「选择元素」直接发起 `captureContext`，进入点选；再次点击、⌘E 或 Esc 取消（沿用 `cancelContextCapture`）。替换「采集到会话 ⌄」弹层：工具栏只有「选择元素」与接收者按钮（如「→ Agent 会话 ⌄」），接收者按钮打开原生菜单（`capture-receiver`），列出本空间会话、「新建会话」与「打开接收会话」。
- 默认接收者按序取：① 用户在接收者按钮中显式选择且仍有效的会话；② 与该网页同屏可见、最近活动的会话；③ 本空间最近活动的会话；④ 都没有时在发起时自动新建「{网页标题} · 会话」。多个同屏候选都没有活动记录时按窗格顺序取第一个。默认值在开始采集前显示在接收者按钮上。“最近活动”是展示偏好，每次使用前对照当前快照核对会话仍存在。
- **采集发起时冻结接收者和页面身份（沿用 `requestId` 与导航令牌）；发送时冻结任务输入。** 改接收者只影响之后的采集。重复触发（连点、⌘E 与按钮同时）不创建多个会话或请求。
- 自动新建的会话标记为“自动创建且未使用”。采集被取消且该会话没有消息时关闭它的标签；现有命令不能完整移除会话时只关闭标签，并在执行记录中说明（R8）。
- 采集完成且用户未发生新导航时有条件展开：接收会话已在某窗格可见时只更新该会话；否则优先放入空窗格；未满四窗格时在源网页旁新增分屏；不替换其他已占用窗格。窄窗（<1080px）、四窗格已满或导航已变化时不改布局，只保存证据并在网页状态槽提示通道显示“已采集到 {会话} · 打开”。
- 自动展开成功后，Main 先 `window.webContents.focus()`，renderer 再把焦点移到接收会话的输入框，使“选择工具 → 点元素 → 输入后 Enter”成立；用户已经导航时不抢焦点（R9）。
- 会话输入框上方显示引用标签 `{元素文字或标签名} · {页面标题}`，可展开查看截图、来源与有效性，可移除。移除只取消本轮引用，保留已保存的采集证据与工程选择。

**S2 单一发送路径与工程绑定。**

- 底部输入框是唯一的目标输入；「发送」继续执行 `confirmTask` → `startRun`，防重复提交，失败保留草稿。
- 「任务」视图删除“修改目标”文本框与「确认任务（生成新版本）」；「采集目标元素」由 S1 取代。
- 输入框上方新增可折叠的「任务设置」，默认折叠，折叠时显示摘要（如“范围 1 · 验收 2 · 终端 A”）。其中保留：允许修改范围、验收条件（仍经 `saveTaskCriteria`）、原「附加目标」select 中的文件/终端/SSH 目标选择（仍经 `saveTaskTarget`）、W4 的 Harness 与 Profile 选择（仍经 `setSessionHarness`）。网页目标由引用标签决定。
- **工程绑定是开关，不是选择器（R5）**：空间有 App 时显示可移除的标签「工程：{App 名}」，移除后可再次开启；没有多工程选择。会话草稿保存独立的工程选择，Main 存 `{appId, projectId}`；renderer 只能提交 `appId | null`，不能提交工程路径或完整 App 对象。首次成功采集受管 App 页面时自动开启；普通网页采集和移除引用不清空既有工程。无工程时明确显示“未选择工程”，不从任务文字推断。
- `confirmTask` 增加 `appId | null` 与页面 `captureId | null`。Main 核对 `appId === w.app.appId`、`captureId` 等于会话当前有效采集，然后冻结 `appTarget`（含 `guestCwd`）与页面证据；`startRun` 继续只接收任务版本身份。App 存在但 `managedApp.guestCwd` 为空时以 `conflict`“App 尚未启动”拒绝并保留草稿。不兼容的页面引用不能静默沿用。
- 恢复不变量改为允许“有工程、无页面”的任务版本；工程身份失效时阻止执行，不降级成无工程运行。
- 历史版本「重新运行」保留在该版本处，语义同原「开始运行」：使用原版本，不重建目标。任务范围、验收条件与 W4 Harness 选择均保留。

**S3 未接入的检查不报故障（D1 = A）。**

- 检查器能力由 Main 明确发布（B4 落点：不持久化的 `ExecutionStatus.checker`，经 `execution:get-status` 读取；`{ connected: true }` 或 `{ connected: false, reason: 'not_integrated' }`）。未接入原因是能力上的结构化标识，不写进检查记录；不把所有 `blocked` 都降为稳态。
- 检查器未接入时，事实层把该状态映射为 steady 的“检查器未接入”（中性形状），不进入问题通道；隐藏「运行检查」按钮，检查区说明“产品检查器尚未接入”；设置页保留说明（与 UX-CONTRACT“能力未接入只在设置页说明”一致）。
- 「接受结果」保持禁用并显示原因；接受仍要求独立检查 `passed` 且适用于当前候选，不新增 `accepted_unchecked`。实际检查失败、失效、其他原因的 `blocked` 继续显示为问题。

**S4 隐藏未接入入口。** 首页「搜索」「打开」模式、会话页「联系人与群聊」、任务页「演示记录」只在开发服务器或 `WSL_DEBUG_STATUS=1` 时出现。首页只保留对话输入与近期空间。不隐藏真实历史、观察结果或 W4 配置入口。

**S5 原生菜单。**

- 在现有 `window.studio.shell` 下新增 `showMenu`，顶层仍为 6 个键。`menuId` 是协议内固定枚举：`tab`、`pane`、`run-records`、`web-more`、`capture-receiver`、`new-tab`；上下文用严格 schema 校验。Main 核对可信来源，按当前快照构建菜单，经 Electron `Menu.popup()` 展示，返回选择项与冻结目标，取消返回 `null`。
- 菜单本身不执行业务：renderer 处理展示动作，业务动作调用现有命令。迟到选择不得转向新空间；依赖布局或排序的动作沿用版本冲突检查。
- 时序（R3）：`showMenu` 的结果由菜单项 `click` 决定；关闭回调中延后一个 tick 再判定为取消（macOS 上关闭回调可能早于 `click`）。Main 把坐标限制在窗口范围内；键盘打开的菜单定位在当前焦点元素处。
- 迁移的六类菜单离开遮挡集合，打开时原生网页保持可见；临时侧栏、状态槽「另有 N 项」列表、⌘K 面板、对话框继续使用遮挡集合。
- 标签菜单可由「···」或右键打开，删除「关闭菜单」项；「上移」「下移」保留作为拖动排序的键盘等价操作。
- 窗格菜单与窗格头按钮合并：窗格头只保留标题、专注、更多（⋯）；分屏、平均分割、关闭窗格进入更多菜单。

### OPS-b（本轮做 S6–S9）

**S6 一键新建。**

- 侧栏标题旁的网页、终端、会话按钮直接创建，不弹对话框；文件、SSH 等仍需必要信息的类型使用现有表单并预填环境。底部「新建标签」改为原生菜单（`new-tab`），列出全部类型。
- 自动命名：网页为“新网页”；终端为“终端 · {环境名}”；会话为“会话 {n}”。
- 网页标题（R7）：只持久化 `autoTitle` 标记，显示的标题由预览页面标题派生；Main 不在导航时改写 `tab.title`。用户重命名后停止跟随，导航和重启均不覆盖手动名称。旧标签默认手动标题模式。
- 双击标签标题或按 F2 进入同一就地重命名流程；取消或保存失败保留原名称。
- 默认环境：先按资源类型能力过滤；只有一个可用环境时直接使用；有多个时用本空间该资源类型上次成功使用的环境。偏好按设备、空间和资源类型保存，仅在创建成功后更新。默认环境失效或两条都不成立时回到表单，不静默改用另一环境。
- 终端创建后仍需用户显式连接；创建会话不自动发送消息。网页标签创建后聚焦地址栏。

**S7 关闭与重开。** 垂直标签悬停时显示 ×。⌘W 关闭活动标签，语义保持“关闭标签、保留实例”；没有活动标签时 ⌘W 不做任何事，不关闭窗口。⇧⌘W 关闭窗口。后台资源区保持现状。

**S8 快捷键。** 扩展 `ShellCommand`；菜单加速键先确认 `BrowserWindow.getFocusedWindow() === window` 再分发（R4）：

**S9 ⌘K 命令面板。**

- 由空间切换器扩展而来，⌘K 与标题栏空间名打开同一个面板。搜索本地快照：空间、标签、会话、最近 50 次运行（按目标文字），以及固定命令（新建标签、切换主题、打开设置等）。
- 沿用切换器规则：输入不导航；只有点击结果或按 Enter 才执行；清除搜索后焦点回到输入框；Esc 关闭后焦点回到原位置，包括原生网页焦点。面板继续使用遮挡集合。

**S10 会话时间线与审阅栏（延后，不在本轮）。**

- 会话合并为一条按时间排序的时间线：用户消息（带引用标签）、任务版本锚点、运行卡、diff 卡、检查卡、Agent 回复。
- 「上下文」「检查」「运行记录⌄」三个子视图移除，内容分别放到引用标签详情、检查卡、运行卡与 diff 卡。
- 版本 / 运行选择改为定位到时间线锚点；指定历史已不可用时沿用现有问题通道文案。
- 最新一次运行完成且尚未审阅时，在输入框上方固定显示审阅栏「接受」/「要求修改」；「要求修改」记录 `changes_requested` 并预填“需要修改：”。
- 统一输入框（F14）：空间会话改用 `Composer`，由 `target` 区分空间会话与个人会话。

本轮现有的统一观察入口（「上下文」视图）、检查视图与运行记录历史保持可用。

## 6. 实施顺序与落点

顺序 B0 → B4 → B2 → B1 → B3 → B5 → B6（R6）。单一 coder 串行写源码与检查脚本；主代理负责规范、审查与验收。

1. **B0 规范与基线**：本文件定稿、验收矩阵、同步 §8 的现行合同，记录基线检查。
2. **B4 降噪与入口清理（S3、S4）**：Main 发布检查器能力与结构化原因；事实层映射；条件渲染。落点：`main/execution.ts`、`main/ipc.ts`（`AppInfo.diagnostics`）、`main/workbench/application.ts`、`shared/status/facts.ts`、`Session.tsx` 检查视图、`pages/*`、`SettingsPage`。
3. **B2 原生菜单（S5）**：协议 `shell.showMenu`、preload、Main 菜单构建与校验，迁移六类菜单并移出遮挡集合。S1 接收者菜单与 S6 新建菜单依赖这一步。
4. **B1 工程与引用分离（S2 的 Main 部分）**：草稿工程选择、`confirmTask` 的 `appId` / `captureId`、任务冻结、schema 5 迁移、恢复校验。
5. **B3 核心点选与发送（S1、S2 的界面部分）**：默认接收者、引用标签、条件展开与焦点、任务设置、唯一发送入口。
6. **B5 高频操作（S6–S9）**：一键新建、`autoTitle`、关闭、快捷键、⌘K。
7. **B6 整体验收**：最终 diff 审阅、全量回归与真实窗口检查。

预计需要修改断言的 E2E（按“采集到会话”“选择元素”“确认任务”“运行记录”“新建标签”等文案检索）：`workbench`、`workspace-observation`、`workshop-actions`、`status-surface`、`review-regressions`、`p0-run-diff`、`space-remake`、`workspace-runtime`、`resources`、`debug-status`，以及 `helpers.ts`。live 用例（`*-live.spec.ts`）只在授权后复跑。

## 9. 实施解释（决定未直接覆盖，按既有规则取保守做法）

B0 列出的六个问题由主代理按 §7 与既有合同逐条判断：均不新增业务规则，只沿用现有行为或取不改变产品行为的做法。第 1 条最接近产品取舍，交付时请用户复核。

1. **单一 `targetRef`（B3，需复核）**：协议仍只有一个任务目标，沿用旧「附加目标」单选的语义——最后一次显式操作生效且始终可见。采集页面后引用标签即为目标；在「任务设置」中改选文件/终端/SSH 目标会替换页面引用标签，再次采集会替换设置中的目标；工程开关不受影响（R5）。不新增“多目标”或优先级规则。
2. **R8 标记不持久化（B3）**：“自动创建且未使用”只在该次采集请求的生命周期内由 renderer 展示状态记录；采集不跨重启，重启后遗留的空会话按普通会话保留，不自动删除用户数据。
3. **`blocked` 记录（B4）**：“检查器未接入”稳态只由能力 `connected: false` 加上检查仍为 `not_run` 推导；任何 `blocked` 检查记录（含历史记录，以及直接经工作台命令调用 `runValidation` 新写入的记录）维持现有问题呈现（计划“不把所有 `blocked` 都降为稳态”）。`runValidation` 的 Main 行为与持久化格式不变，本轮不给检查记录加结构化原因；产品界面在未接入时不再提供「运行检查」，所以正常操作不会产生新的 `blocked`。
4. **“通过且适用”fixture（B4）**：只在测试中产生——单测直接经应用端口写入检查结果，E2E 预置 `workbench.json`；不新增产品代码路径或测试环境变量门控的假检查器。
5. **F15（App 图标）**：不在 S1–S9 范围，本轮不改。
6. **偏好存放（B3/B5）**：按计划 §3“按设备、空间和资源类型保存”，默认环境与最近活动会话都存为本设备展示偏好，每次使用前核对当前快照；不写入 Main 业务持久文件。
7. **首次 App 采集自动开启工程（B1）**：计划“首次成功采集受管 App 页面时，建立可见的工程默认值”。schema 5 为每个会话持久化“是否已决定工程”的标记（迁移为未决定）；Main 在采集完成的同一次写入中，对未决定的会话按本空间 App 开启工程并标记已决定。用户显式开启或关闭都记为已决定，之后的采集不再改动；普通网页采集与移除引用不清空工程。这样默认路径保持 `fe3684f` 中“App 页面任务绑定工程”的行为。
8. **App 页面引用要求开启工程（B1）**：计划“不兼容的页面引用不能静默沿用”。引用受管 App 页面而工程关闭时，`confirmTask` 以 `conflict` 拒绝并保留草稿，提示开启工程或移除引用；工程与普通网页、终端、文件目标的组合照常允许。执行开始时不从页面重新推断工程。
9. **确认时核对工程选择（B1）**：`confirmTask` 携带的 `appId` 必须等于会话已保存的工程选择，否则 `conflict`；renderer 先等待未完成的工程开关保存，再确认任务。
