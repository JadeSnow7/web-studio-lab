## 独立恢复演练与后续恢复方法

档案根的 `restore_check.py` 和 `restore-verification.json` 记录一次真实恢复演练：从 `repository-before-sync.bundle` 建立独立 clone，detached checkout 原 HEAD `ea3bad9`，应用 staged / unstaged patches，再从 snapshot 还原 untracked、显式包含的 ignored 文件和完整权限。最终 5,219 项 manifest 的内容、类型、mode 与 symlink target 完全一致；HEAD、status、index stage、staged / unstaged patches、tracked / untracked 清单均与原回执逐字节一致，源档案复核未变。

首次恢复发现 31 个 tracked 文件的原 `0600` 权限经 Git checkout 变为 `0644`：Git 只保存可执行位。修正恢复方法为先核对 patch 恢复的内容，再按 manifest 恢复完整权限；首次失败与修正摘要保留在结果回执，不改写为首次通过。最终恢复目录使用 detached HEAD，因此 symbolic ref 与来源分支不同；未恢复依赖等 ignored 内容，因此 ignored inventory 不作相等判定。

需要恢复时，先读持久档案中的演练脚本和机器结果，将 `restore_check.py` 与其依赖 `preserve.py` 复制到新的临时工具目录。只修改副本中的 `BASE` / `RECOVERY`，使其指向新的、不存在的恢复目录；`ARCHIVE` 继续指向持久档案。随后运行副本，结果写入副本工具目录。不要直接运行档案内的原脚本：`RESULT` 位于脚本同目录，直接运行会覆盖原验证结果。档案原脚本、receipt、snapshot、patch 和 bundle 均保持不变。

恢复只针对独立 clone，逐项核对 manifest 和 Git 回执后再审阅结果；不要将恢复脚本输出指向当前主工作树或任何原 edu 路径。不能仅应用 patch 而遗漏未跟踪文件、ignored 日志及完整文件权限。
