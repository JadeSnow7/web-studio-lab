# 空间 App 模型与编辑验收

本轮从 `v0.1.5`（`cf62dc74f49e7f9e81598be7b9e5109cf5946e9c`）建立独立工作树，交付空间内单个标准 App 的持久描述、创建及编辑界面，并保留原生 Browser 的元素采集与任务修改入口。实现前目标源码干净；本轮不提交、推送、发布或调用真实模型/sandbox live。

## 模型与边界

- App 描述有稳定身份、所属空间、关联项目、名称、说明及编辑版本；Main 是唯一写入者，renderer 仅保存草稿和展示投影。
- App 描述、项目、运行实例、Browser 资源和任务各自保持身份。名称/说明编辑不创建工程、不启动或停止运行实例。
- 每空间仍只有一个标准 App；不增加多 App、第二模板、云部署或完整代码编辑器。
- 旧版本保存数据显式迁移，保留 projectId、resourceId 和任务历史，不自动启动应用或执行任务。较新未知版本拒绝加载，保留原文件。
- App 页面继续使用原生 Browser 的同页采集。确认任务冻结项目与元素定位；导航、重启或实例更换使旧现场失效。页面内容不能授予权限。
- 此处“修改”覆盖 App 描述编辑与既有元素修改任务链路的保留/补全；真实模型修改结果不由离线 fixture 推断。

## 固定验收

| 编号 | 输入/操作                                              | 预期与验证                                                                                 |
| ---- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| A1   | 空间中创建有名称/说明的标准 App                        | 描述与 runtime 同一 workspace/project；禁止重复创建；失败可见且不掩盖已产生的副作用        |
| A2   | 编辑名称/说明                                          | 同一 appId/projectId；版本递增；保存后展示和重启读取一致；不修改运行状态                   |
| A3   | 空输入、重复提交、旧版本、切空间后的迟到操作、存储失败 | 字段错误/冲突明确；保留草稿；不覆写其他空间或新状态；无伪成功                              |
| A4   | 读取 v0.1.5 数据和未知较新 schema                      | 前者保留工程/资源关联；后者报错且不写原文件；不自动启动进程                                |
| A5   | 从 App Browser 点选元素、确认修改目标                  | 保留具体元素和页面身份及关联项目；结构化定位进入不可变任务；过期现场拒绝开始               |
| A6   | 实际 Electron 窗口创建/编辑/取消/错误、键盘和窄窗      | 符合 DESIGN/UX-CONTRACT，同一空间布局和共享控件；截图检查；fixture 与真实 sandbox 分开报告 |

## 实现前证据

- Node `v26.5.0`；仓库规定 pnpm `10.34.6`。系统 pnpm 实际为 `11.25.0`，首次安装自动改写配置并报 ignored builds，保留日志并恢复其配置副作用后使用规定版本。
- 直接调用已安装 Vitest 的原有 `managed-app.test.ts` 与 `application.test.ts`：35 tests passed（2 files），见 `baseline-tests-direct.txt`。最初通过系统 pnpm 发起的检查被依赖安装阻断，见 `baseline-tests.txt`，不能算测试执行结果。
- 完整回归、构建、文档检查、离线 VS001 自检及 UI 检查在实施后记录，不继承历史通过结论。
