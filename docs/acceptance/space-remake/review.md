# SR-1 主线程与独立审查

本记录区分静态审查与运行证据。最终命令和窗口结果见 task-summary.md；此记录本身不授予通过状态。

## 已定位并交给唯一 coder 的问题

- 窄窗固定栏临时展开后，宽窗释放遮挡但留下 peek；再次缩窄会出现未经隐藏确认的浮层。`ui-narrow-roundtrip-before.txt` 保存实现修复前的真实失败，修复清除临时 peek，保留 pinned 和分割树。
- 多浮层 Esc 需要按最上层来源处理并阻止同一事件继续关闭下一层；待展开菜单也需要处理取消。菜单延迟焦点恢复不能覆盖后续浮层关闭后的触发器焦点。
- 页面导航、专注模式与快速开关必须取消 pending 来源；Browser 的最终布局发送检查 pending/visible 遮挡集合，避免迟到 ResizeObserver 重新显示原生网页。
- 同空间 locateSession 无条件隐藏网页，分屏 visible 投影未变化时无法恢复。修复只在跨空间定位时主动隐藏，同空间布局继续由 renderer 投影负责。
- 通知边缘触发区曾覆盖固定栏关闭按钮；改为只让气泡按钮接收指针，右侧预留空间属于外壳。
- 终端从旧 flex 容器迁入绝对定位窗格后未填满可用高度；截图检查发现后补齐空间终端高度约束。
- 首页新建空间对话框位于隐藏空间页祖先下；改为全局 portal，取消后回到首页原入口。
- DevTools 首次打开时，严格请求过滤器阻止了尚未绑定身份的原生前端。现在先创建并登记专属 DevTools 窗口，再打开前端；豁免严格限制为该窗口的 GET 与标准 bundled URL，其余请求仍沿用原策略。回归经真实菜单关闭、重新打开，检查窗口、URL、DOM 和所属网页；直接 webContents 调用只保留为早期诊断，未用作通过证据。
- 原生设置页暗色截图发现旧提示条与表头仍有硬编码颜色。由唯一 coder 将共用样式映射到既有语义 token，补测设置页对比度和受影响窗口；修复前截图保留为 `native-window/05-settings-dark.png`。
