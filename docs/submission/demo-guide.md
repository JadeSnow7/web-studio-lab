2. 记录 commit、未提交文件清单、源码散列、构建指纹和模板版本。历史基线为 `b5531e1ac3b3da7adf000f6ba61f2c5b19a0755f`；当前候选分支为 `agent/submission-20261016`，实现 commit 为 `120d34777db305b99e9501951363fe64e049a69f`。推送状态与准确版本以[PR 整合记录](../acceptance/submission-20261016/README.md)为准，不能用基线 HEAD 代替完整候选或录像快照。
3. 为真实 AI/终端准备可用的 sbx、guest Codex、既有认证及网络。在本机完成配置，不把凭据或 profile 放入材料。
4. 使用全新演示空间和 App，不重置已有手帐库；需要重拍时另建实例。外部魔塔使用有权使用的隔离源码副本，不编辑原件。

从相应候选的仓库根目录执行：

```sh
pnpm install --frozen-lockfile

```

`pnpm dev` 包含服务构建与桌面启动。使用外置构建目录的机器先按[外置构建说明](../development/external-builds.md)核对挂载；不要在别人的录制工作树执行。未配置 sbx 时桌面可启动，不能据此认为真实模型与终端已就绪。

## 场景一：已有魔塔工程

1. 在空间 App 对话框选择“导入已有工程”，通过原生选择器选兼容魔塔工程。检查静态预览中的文件数量、体积和摘要，再确认导入。profile 上限为 512 文件、64 MiB、单文件 12 MiB；不执行来源工程的安装或服务脚本。
2. 打开同一受管 App 的游戏和编辑器，分别为 `/index.html` 与 `/editor.html`。手动编辑只允许副本中的 `project/floors/MT1.js`、`_server/config.json`；关闭页签不会停止 App。
3. 在会话任务中选择当前游戏页，输入固定路线和检查点，明确授权游戏操作。路线定义见 `e2e/mota-agent-live-helpers.ts`，真实模型入口见 `e2e/mota-agent-live.spec.ts`；不要用另一条路线要求相同数值。
4. 普通新局逐项核对 12 个有序检查点及终点 MT4 `(11,10)`、HP926、money7、coin0。
5. 新任务额外授权一楼放置幸运金币。让 AI 仅把 MT1 `(6,10)` 的空格 `0` 改为 `53`，保留前后文件与操作回执。新局走同一路线，核对相同终点、HP926、money14、coin1。
6. 正常停止 App 并核对所属清理状态，另记无法确认的进程/端口项。不要把“页面关闭”当作停止完成。

这不是通用导入或任意 AI 改码。Mota 不支持源码导出，也不产生标准 P0 D 的 Agent-run diff。自动化 live 用例的权限、全新目录与摘要前置条件见根 [AGENTS](../../AGENTS.md)；默认跳过不算通过，fixture 工具轮与真实模型轮分开记录。

## 场景二：从模板生成手帐

1. 新建标准 App，记录项目/实例身份与模板版本。标准模板有种子数据，不称“完全空数据库”。
2. 提交生成手帐的目标，并明确允许修改的项目范围、保存与刷新验收条件。可以用“左侧月历、右侧正文、心情、标签与来源字段；本地保存并支持刷新重开”作示例，不放入真实私人记录。
3. 核对实际源码改动、检查结果和受管启动。使用虚构测试内容正常保存，再刷新重开同一日期，逐字段比较；记录鼠标、键盘或人工操作的实际执行者。
4. 对公开研究另行授权。本轮执行新搜索后，读取可访问正文并显式纳入，再给出建议。分别保留搜索、正文读取与纳入回执；缺候选 URL 时不推断来源属于哪次搜索。
5. 由 AI 经正常 UI 填写、保存和刷新重开。AI 操作与人工独立刷新分别取证。保存前后检查同一项目/实例/日期、完整字段和错误状态，不用“任务结束”代替持久化验收。
6. 遇到目标未绑定、过期引用、定位失败、取消或重试，保留旧 run，重新确认目标后另记结果。停止前核对所有所属资源，保留未决项。

完整 v5 彩排有取消和续跑，保留为历史。正式生成、17 日研究保存与 18 日补录分别验收：17 日业务链路通过但录屏中止，18 日在空白日期重新执行，AI 保存及 AI 自身刷新、人工独立刷新通过，17 日四字段保持原样。正式 130 秒成片已完成。Wikivoyage 回执缺陷、17 日 UNESCO 403 与一次 Control+Home 被拒保留；后者发生在保存刷新之后，随后普通滚动成功。18 日 18 份 MCP 回执无失败，不表示此前缺陷已修复。

魔塔目录选择、确认导入、输入路线、授权和切页是人工操作，路线内的游戏操作与受限改图由 AI 执行。第二轮开局/拾币发生在 Agent 页显示期间，以工具回执确认；差异卡是实际文件派生的说明画面。

手帐生成前有人工目标元素采集，该点击未录入续录；后段成品展示由人工切到 App。会话页画面不能描述为直接拍到了保存按钮动作，相关字幕应写“回执确认”。鼠标失败后使用键盘成功，不剪成鼠标一次成功。18 日录前再次人工采集目标，采集点击未录到；正文输入开头也未直接录到，完整四字段一致依靠回执。人工切页、独立刷新、重选日期和只读展示均在成片说明中区分，不能拼成一次连续 AI 操作。

保留原片、时间线、片段区间、实际倍速、删去区间、执行者、run 与证据散列。视频结构/解码通过与功能验收分别判断；保留“比赛环境未就绪”提示。手帐成片共 15 个片段，使用原速、2×、3×、4×、8×，具体区间与倍速见最终编码回执和剪辑计划。32 张顺序解码样本目检及主控另查其中 14 张均通过，但不是逐帧隐私保证；公开分享前仍需确认画面范围。
