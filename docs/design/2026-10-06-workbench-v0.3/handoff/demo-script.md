# 比赛演示顺序

演示围绕“看见问题→点选→确认→修改→检查→证据→人工决定→独立复验”，用于让评委理解闭环；不声称来自官方评分标准，不编造权重。

## 当前可展示的真实功能

1. 打开当前Electron工作台，空间页Workshop固定、Browser加载本地演示任务页。说明问题来自这张可见页面。
2. 点击“选择元素”，真实点击任务元素；展示元素摘要、URL、采集时间、同一webContents与元素/页面截图。
3. 编辑C1任务目标、允许范围、验收与预算；确认后展示本次启动内存中的不可变版本。当前默认最多3次attempt、15分钟。
4. 导航使旧现场失效，重新采集后才能确认；可以展示已有导航失效路径。CDP真实断开/重附着此前没有实测，不把它作为现成验证结果。

以上以 [README当前状态](../../../../README.md#L9) 和 [历史窗口验证](../../../verification/2026-10-06-desktop-ui/README.md#L33)为依据。任务版本与截图尚未持久化；重启后可恢复不是现有能力。

## v0.3可点击交互演示

明确切换到设计原型，持续显示“交互演示”。下面的文件变化、检查、证据、用户决定与复验记录都是确定性模拟数据。

1. C1起点：任务没有优先级。点选任务后确认新增`priority`，low/medium/high、默认medium；允许UI/API/迁移/类型范围；固定验收保持只读，补充条件另列。
2. 开始演示，展示阶段与文件变化。命令退出后仍等待服务ready；服务ready后才检查，不能把任何一个阶段当作完整通过。
3. 逐项展示编辑保存、API一致、旧数据迁移、同一数据目录API冷启动后保留。打开检查对应证据，注明API或独立Playwright环境；用户观察/Agent操作仍绑定可见页面。
4. “检查通过，待你审阅”：查看摘要与diff后接受，接受绑定任务版本和具体源码；也可要求修改，回确认后形成新版本、新run，旧记录保留。
5. 在只读历史选择来源run，检查完整源码快照、固定验收版本、清理完成，再显式发起无模型复验。展示新记录和来源run；不调用模型、不覆盖旧记录、不继承原接受。
6. 重置走失败修复分支：attempt 1冷启动失败→证据→剩余预算→反馈来源→attempt 2。整个run仍为3次/15分钟上限，不重置预算。
7. 重置走取消/工具故障分支：取消请求后仍“取消中”，等待清理完成；检查工具故障显示“无法判断”。再展示CDP断开→旧现场失效→重附着→重新采集的恢复约束。

补充用例只展示正确目标，不展开第二条主路径：C2为A修改自己的任务成功，B直接请求API拒绝且数据不变，隐藏按钮不足以证明权限；C3为初始前端`deadline`纠正为`dueDate`，检查类型、真实请求/响应、保存与展示。旧画板“C1截止日期/C3负责人字段”保留在baseline，不用于新叙事。

## 工程接通后才能展示的能力

Codex真实修改、独立执行服务、真实启动与ready、固定检查、进程清理、持久化证据与任务/审阅、完整快照导出、无模型复验及重启可读历史均需工程完成并取得对应证据后，才替换原型演示片段。每替换一段应标实际run、任务/源码/验收版本及真实来源；原型通过不证明这些能力。

结尾展示交付源码与证据入口，说明通过、失败、无法判断以及人工决定各自含义。证据缺失保留原结论但标不可核对，不把演示状态混入真实比赛运行统计。

本文件是演示脚本建议；不宣称本轮原型路径、两尺寸或发布后回读已验证。实际结果由证据目录与主线程最终报告记录。
