# Web Studio 工作台增量设计 v0.3 — 冻结设计契约

来源：用户于 2026-10-06 明确批准的完整实施计划。设计只读参考主仓库当前文件，不以当前聊天旧 worktree 的 README 判断实现状态。

## 范围和所有权

只写本目录。baseline 保存原 Claude Design 原样导出，不更改；prototype 保存基于导出的增量可编辑源。主线程负责 Spec、审查、实际操作与最终结论；coder 是 prototype 唯一写入者；文档 agent 只写 handoff 三份说明。原 Claude 会话只导出和按最终本地源发布新 artifact，不改旧 artifact 或应用代码。现有125个文件哈希在 evidence/repository-baseline.json。

## 已冻结决定

- 空间页直接开始、Workshop 固定、未采集；六入口保留。
- 1440×900 主画板；1024×720 下 Workshop 内容320px、右栏默认收起按需覆盖，临时侧栏互斥。
- 延续七个用户指定颜色、系统中文字体、44px顶栏、56px导航、360px左内容与340px右栏。
- 全程显著“交互演示”，不发起真实执行、模型、业务API、消息或系统进程操作。
- 首层只展示问题、进度、结果、下一步；工程详情按需展开。状态使用文字和形状。
- 用确定性模拟事件推进、暂停和重置；演示控制条在产品画面外。

## 用例与记录

C1：priority low/medium/high，默认medium；编辑保存、API一致、旧数据迁移、API同一数据目录冷启动保留。C2：A改自己的任务成功，B直接API请求拒绝且数据不变，含UI提示。C3：前端deadline修为dueDate，类型、真实请求响应、保存展示与原流程。固定检查与补充条件分开，不修改固定检查的含义。

在线run预算≤3 attempts、总时限≤15分钟；自动修复同run、累计预算。目标、范围、验收、预算或现场引用改变后重新确认形成新taskVersion。用户意见须确认后进入执行输入。人工要求修改保留旧run并回草稿，不复活终态。执行、命令退出、服务ready、自动检查、清理、用户审阅分别表示。

接受绑定taskVersion与source snapshot；新版本/新源码/新复验不继承接受。历史只读，不触发页面控制。无模型复验前置：清理完成+完整源码可读取+固定验收版本；显式创建新run，关联sourceRunId、source snapshot hash、taskVersion、acceptanceHash；不调用模型、不改旧记录。缺失证据保留原检查结论，另示“证据不可核对”。
