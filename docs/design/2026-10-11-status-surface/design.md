# 降噪设计（修订 2）

基线 `917f375`。本文件定义「显示什么、在哪里显示」；数据结构见 [status-interface.md](status-interface.md)，修订原因见 [review-response.md](review-response.md)。

## 1. 原则

- **正常即安静，异常才出声。** 健康稳态只画形状；文字以视觉隐藏文本和悬停提供。
- **每条状态只回答一个问题：用户现在要不要做点什么，或能做的事变了没有？**
- **控制权、进行中和未确认的事实从不被折叠。** 它们不和错误竞争同一个位置。
- **隐藏不是丢弃。** 所有状态都进入同一份事实列表；界面按通道取用，诊断面板看全部。
- **文案单一来源。** 组件不再拼接 `执行：${run.state}`，也不再自行判断状态，只读 `useStatusView()` 的结果。
- **不变量说明不是状态。** 「隐藏继续运行」「收藏与快照分别保存」等不常驻，改为一次性提示或帮助内容。
- **能力未接入不是故障。** 「比赛执行与验收（T04）尚未接入」只在设置页说明，不报警。

## 3. 状态种类与呈现

每条事实有一个 kind（定义见 status-interface.md §2），kind 决定呈现：

| kind | 例子 | 呈现 | 何时消失 |
| ---- | ---- | ---- | -------- |
| `control` | AI 正在操控此页面；已暂停 AI 操控（允许 AI 继续） | 常驻通道 | 事实消失 |
| `unresolved` | 模型已停止，App 数据操作仍待确认（重新核对）；所属进程退出未确认；SSH 远端进程未确认；停止后的清理未确认 | 常驻通道 | 事实消失 |
| `progress` | 正在执行…（取消回复）；正在取消并核实退出…；正在连接…；正在启动应用… | 常驻通道 | 事实消失 |
| `problem` | 页面加载失败；已拦截导航；页面控制已断开；连接失败；检查已不适用；现场已失效；覆盖不完整；文件可能变化 | 问题通道：最高一条 + 「另有 N 项」 | 事实消失 |
| `confirmation` | 已关闭，所属进程已确认退出；历史已恢复… | 提示通道 | 用户与该窗格交互后（确认失效规则见接口 §6.3） |
| 展示层 hint | 采集指引；已收藏到我的资源；正文快照已保存；首次打开文件标签的说明 | 提示通道 | 用户关闭、与窗格交互或切换（按 hint 定义） |
| `steady` | 已连接；服务运行中；执行完成；检查通过；现场适用性：有效 | StatusDot + 视觉隐藏文字 | — |
| `capability` | 比赛执行与验收（T04）：尚未接入 | 仅设置页与诊断面板 | — |
| 诊断数据 | runId、instanceId、generation、seq、原始枚举、evidenceRef、PageCapture JSON | 仅诊断面板 | — |

**唯一会因交互降级的是 `confirmation` 与 hint**。`unresolved` 不降级：SSH 未确认、清理未确认在事实改变前一直显式。

**元数据不是状态。** 观察结果的来源、环境、时间、范围、版本 / 散列放在结果的「来源」折叠区，用户展开即可见（满足合同「散列可见」）；它们不进状态系统，也不是诊断专属。

## 4. 展示组件

### StatusDot（steady）

沿用 `components/Badges.tsx` 的「形状 + 颜色」约定：

| phase | 形状 | 颜色 token |
| ----- | ---- | ---------- |
| `ok` | 实心点 | 成功色 |
| `pending` / `active` | 缺口环 | `--accent` |
| `idle` | 方块 | 中性灰 |
| `failed` | 三角 | 失败色 |
| `unknown` / `degraded` | 虚线环 | 警告色 |

形状 `aria-hidden`；`label` 以 `sr-only` 文本紧随其后；悬停 `title` 为 `label` + `detail`。

### StatusSlot（每个窗格一个，三条通道）

```
┌ 常驻通道  control → unresolved → progress，全部显示，每条可带动作
├ 问题通道  最高优先级 problem 一条 ·「另有 N 项 ▾」
└ 提示通道  一条 confirmation 或 hint ·「知道了」
```

- 三条通道都为空时高度为 0。条目进入时以 `role="status"`（problem 为 `role="alert"`）播报一次，降级或折叠只改变视觉，不重复播报。
- 「另有 N 项」展开为菜单列表，进入 occlusion 遮挡集合；方向键移动，Esc 关闭并回到触发器。
- 常驻通道条目的动作按钮在 Tab 顺序中位于窗格工具栏之后、内容之前。

### 全局出口

- 一次性失败（界面操作失败、工作区命令错误）进 **Toast 队列**：最多 5 条，失败类不自动消失。替代 `workspace.error` 横幅、`ErrorToasts` 与资源页的瞬时 Notice。
- 无窗格归属的持续条件（对话不可用、环境未就绪、安装出错、重启后生效）进**标题栏**按钮，进入设置页（实施期修订，见 review-response.md）。
- `storage` 持久化失败保留**底部横幅**（全局降级，必须持续可见）。

## 5. 逐区域改造

**标题栏**：健康时右侧只留铃铛。现有「Codex CLI · 对话已连接」按钮在健康时移除；对话不可用时出现「Codex CLI · 对话不可用」按钮；比赛环境存在问题（未就绪、安装出错、重启后生效）时出现「环境 · {问题}」按钮（取最高优先级一条，其余以描述说明），均进入设置页（实施期修订）。健康时进入设置走左栏「设置」或 ⌘,。

**侧栏**：去掉「已显示」；标签行尾 StatusDot（终端已连接 = 绿点，按决策 2 保留；执行中 = 环；失败 = 三角）。页脚规则说明移除。「后台资源 / 已关闭标签」保留原文并附计数，无内容时不显示。

**网页**：

- 工具栏：后退 / 前进 / 刷新 / 地址 / 选择元素 / **采集到会话 ⌄** / **⋯**。
- 「采集到会话 ⌄」：选择关联会话、新建关联会话、采集到所选会话、打开关联会话。
- 「⋯」：收藏到资源、保存正文快照、查看空间资源；受管 App 网页为「管理 App」。
- 两个菜单 `role="menu"`，展开前进入 occlusion 遮挡集合；菜单项名称与现有按钮名称一致。
- 「沙箱应用 · 服务运行中」降为 App 图标上的 StatusDot。
- 状态全部进入 StatusSlot：AI 操控 / 已暂停与「选择中」在常驻通道；加载失败、点选失败、断开、拦截、不可用在问题通道；采集指引与收藏 / 快照结果是 hint。

**终端**：标题栏胶囊「sandbox · workspace」（环境 + cwd 末段 + StatusDot），悬停显示沙箱全名与绝对 cwd；「中断（Ctrl-C）」「关闭终端」改为标题栏图标按钮，可访问名称不变。页脚说明移除。连接中 / 关闭中 / 进程退出未确认在常驻通道；连接失败、不可用在问题通道；已关闭为 confirmation；输出缺口为 hint（「未读输出超出保留窗口；已从当前窗口重建显示」）。

**会话**：

- 删除「Codex CLI · state · 沙箱由服务决定」与「运行 {runId}」两行。
- 视图收为「对话 / 任务 / 上下文 / 检查 / 运行记录 ⌄」（日志、diff、报告）。
- 底部状态条即会话的常驻通道：执行中 / 取消中与「模型已停止，App 数据操作仍待确认 · 重新核对」可同时出现。
- 检查页的执行 / 检查 / 适用性 / 审阅改为中文 label 与 StatusDot；检查已不适用、检查无法执行进问题通道。
- 版本 / 运行选择移入展示状态；查看历史时「现场适用性：历史采集（不表示当前现场）」。
- 「诊断详情」移到诊断面板（面板内查看，不可导出）。

**输入区**：可访问名称**不变**——Session textarea 仍为 `aria-label="会话消息"`；「发送到 · …」改为 `aria-describedby` 指向的视觉隐藏描述。Composer 的「发送到 · …」`<label>` 保留但视觉隐藏，名称不变。快捷键说明改为发送按钮 `title`；Composer 的发送阻止原因（`notice`）仍显式。

**观察 / 文件**：结果顶部只外露进行中、失败、覆盖不完整、可能变化；来源、环境、时间、范围、版本 / 散列在「来源」折叠区。Files 顶部「仅访问已授权根内的文件 · 浏览不加入 Agent 会话」改为首次打开的 hint。

**App 对话框与编辑器**：标题显示 `workspace.app.name`；说明为空时不显示占位；服务状态为 StatusDot + label；启动中 / 停止中进常驻通道。`AppEditor` 的保存中状态行属于表单反馈，保留原样。

**首页**：「不读取其他空间」「可从个人收藏中选择…」改为输入区描述的悬停。空间卡片计数保持不变；有运行中任务时卡片标题旁加 StatusDot。

**设置页**：保持现状，继续展示 Codex 版本、沙箱、cwd 与「比赛执行与验收（T04）」能力说明。设置页本身就是状态的主场，不做降噪。

## 6. 可访问性与键盘

- 视觉上移除的文字必须仍在视觉隐藏文本、`aria-describedby` 或可展开内容中；`role="status"` / `role="alert"` 随条目迁移到 StatusSlot，不删除。
- 常驻与问题通道的条目视觉可见、动作可用 Tab 到达；验收用可见性与键盘断言（plan.md §5）。
- 两个新菜单与「另有 N 项」列表支持方向键、Esc 关闭并恢复触发器焦点，遵循现有浮层规则。
- 通知按钮可访问名称继续包含未读数。

## 7. 不做的事

- 不改 Main 业务状态、命令或持久化格式；不新增业务状态所有者。
- 不新建全局导航、右侧会话或独立配色；不做事件总线、插件或动态注册。
- 不改变取消、清理、归属的判定；只改变它们被呈现的位置与时机。
