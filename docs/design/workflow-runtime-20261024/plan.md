## 实验修订

所有实验保存版本清单、脚本与输入 hash、seed、配置、输出、断言结果、失败及人工干预；重跑用新的证据目录。MockHarness 按逻辑调用和 attempt 返回预定结果，延迟/fault 序列由 seed 固定，不能以概率实现不可复现的失败。fixture 录制只保存获准、脱敏后的输入输出，凭据和未授权正文不得进入回归集。

## E9 对照与决策

仍使用 edu/Mota 的固定任务：类型错误修复、鉴权缺陷审计、组件迁移和覆盖率补齐。实施前记录两个工程的可访问路径和 commit/完整输入 hash；预埋缺陷、期望输出、独立验收脚本提前封存，不给被测 Agent 查看真值。Mota/edu 当前具体版本本轮未核对，不能默认采用历史路径。

1. A：单 Agent；B：手写 workflow。两者使用相同 Harness、模型/推理配置、工具权限、输入、验收和总预算。先判断编排本身是否有价值。
2. C：自动生成 workflow，仍固定与 B 相同的单 Harness 条件。单独测规划可靠性和人工介入，不混入模型路由收益。
3. D：在 C 上启用多 Harness。固定各自版本、成本口径与可用路由，单独报告异构能力和成本变化，不能直接归因于 Ultra。

先做每组每任务 3 次配对先导、随机化顺序并记录时段。模型别名无法固定实际版本时记录供应商标识和时间窗口，明确可复现性限制。把规划、失败重试、被停止调用及恢复全部计入总预算；超预算与基础设施失败分别记账，不从失败分母中删除。

原有“至少 3/4 任务通过率不低于 A、审计召回更高、人工干预不增加”保留为先导产品门槛，同时要求审计误报率不高于 A；逐组比较 B/A、C/B、D/C，不能以 B 通过替 C 的失败背书。先导之后根据方差与预期收益预注册扩展样本量、容许的时间/token 增幅及判断方法，新增批次不重选最优结果。未冻结成本容许值前，E9 只报告数据，不批准 Ultra 默认启用。

## 一个完整场景的走查

P0 使用“固定快照中的类型诊断与汇总”：Main 冻结输入与任务授权，单个 readonly worker 产出结构化诊断；结果事务提交后才回 VM；用户停止后，先确认进程退出，再从 Journal 续跑；已提交诊断只复用，不再次调用模型。P1 把独立文件诊断并行化并核对反序完成。

“修到 tsc 通过”放到 P2：

1. 人类请求与明确项目形成固定任务版本及写授权；Main 取得原项目所有者的许可，冻结 S0，并建立 run 候选。
2. readonly 诊断基于 S0 与固定依赖环境，运行产生物进入独立 scratch；schema 校验后保存结果。失败保持 incomplete，不能当“零错误”。
3. 主流程串行启动 lane 修复，每个 attempt 从已发布候选快照建立独立目录。失败不污染下一 attempt；成功经发布事务得到 S1。
4. 若发布后、交付前崩溃，恢复先核对旧进程，在新候选中从 S0 重建前缀并复用 S1，不重做修复。若有用户外部改动，不把 S1覆盖到用户目录。
5. 独立检查对 S1 运行固定 tsc/测试，并将真实结果交下一轮；诊断计数只是停止启发式，不是验收真值。轮次、attempt、时间、成本共同有界。
6. 末阶段模型意见只作参考；最终应用候选须经项目所有者的条件更新与授权。独立产品检查器未接入时显示未接入，不能把实验脚本通过自动转成 TaskRun 接受。

该走查验证职责与恢复决策可解释，不是产品执行证据。

## 下一包的执行边界

下一次实现从 W0 + W1 开始，目标仅是 P0a 的 QuickJS 可行性基线：核对 writable checkout 和 dirty 清单，冻结源格式与预算，先写上述反序完成/取消/资源负例，再实现最小 VM 桥接。输出真实 WASM 运行结果、失败记录和确切 diff，由主线程审阅后才进入 W2。
