# edu pronunciation verification in the desktop

The default edu application keeps scoring disabled. The managed App dialog starts a five-minute, two-call verification session only for the active running student's page. Main derives the workspace, project, original instance and source digest; the renderer sends no provider settings or process arguments.

Main saves a recovery-only marker before requesting ownership. After old audio cleanup, it checks the same resource, native webContents and document generation again and dispatches begin in the same synchronous authorization step. Service separately validates the frozen source and instance. Service events bind the leased instance to the existing preview; only an active matching lease can regain audio permission.

Coding, terminal input and application creation/rebuild are paused globally while verification or recovery is unconfirmed. Leaving the student route or switching away from its active resource requests verification exit and default-mode restoration. Stopping the application revokes scoring but leaves maintenance paused until explicit exit. The dialog shows the remaining time/calls, revocation, restoration and recovery states.

An ended receipt alone does not unlock Main. Main queries the authoritative application and verifies a running, matching-source default instance distinct from both the leased and original instances. A failed query or state save remains locked and reports recovery. Completed session receipts cannot reactivate a lease or pause a later healthy default instance.

Restarted snapshots never restore an active scoring capability. A terminal ended receipt without a Main recovery marker does not create a new recovery UI; unfinished startup events still establish a recovery lock. A marker whose ended health response was lost requires explicit recovery, including a fresh default if the previously restored instance has stopped. A service journal event is retained for late Main listeners; explicit reconcile sends only the journal target identity. If begin never returned a leased identity, the same recovery action instead sends the frozen original begin identity/source through a separate cancel-only admission recovery RPC. Its independent recovery status grants no scoring calls. Main requires the exact service-reserved fresh default instance and verifies its health/source before unlocking. Service owns the journal, process cleanup, old URL checks and healthy default-mode restoration. Main retains the original/leased identities and observed application URLs for recovery display, without audio or credentials.

Offline Main, Host, RPC and presentation tests establish these desktop boundaries. They do not establish real provider scoring, a signed package, physical microphone behavior or product acceptance.
